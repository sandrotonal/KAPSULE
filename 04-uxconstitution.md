# Kapsule — UX Constitution

## Purpose

This document defines how Kapsule should behave.

Not how it looks.

Not how it is coded.

How it feels to use.

Every interaction should reduce cognitive load.

---

# UX Philosophy

Good UX is invisible.

Users should never stop to think.

Every action should feel obvious.

Every screen should answer one question:

"What should I do next?"

---

# Core Principles

Reduce friction.

Reduce decisions.

Reduce clicks.

Reduce stress.

Increase confidence.

Increase clarity.

Increase speed.

Increase trust.

---

# Navigation Philosophy

Navigation should disappear.

Users should rely on recognition.

Not memory.

Everything important should be reachable within two interactions.

Never hide important actions.

Never create deep navigation trees.

---

# Information Architecture

Organize by life.

Not by technology.

Not by file type.

Not by database structure.

Documents belong together because they matter.

Not because they are PDFs.

---

# Search First

Search is a primary feature.

Not a secondary tool.

Users should instinctively search.

Search should understand:

Titles

Categories

Tags

Dates

OCR text

Metadata

Recent activity

---

# Home Experience

Home is not a dashboard.

Home is a continuation.

When opening Kapsule users should immediately understand:

Where they left off.

What matters today.

What they recently accessed.

What needs attention.

---

# User Journey

Open app.

Immediately recognize context.

Continue previous work.

Finish task.

Leave.

No unnecessary steps.

---

# Cognitive Load

Never show everything.

Reveal complexity gradually.

One decision at a time.

One clear action.

One obvious path.

---

# Empty States

Empty states should educate.

Not entertain.

Show:

What this feature does.

Why it matters.

How to start.

Avoid jokes.

Avoid illustrations.

Avoid mascots.

---

# Error Handling

Errors should feel calm.

Explain:

What happened.

Why.

How to fix it.

Never blame the user.

Never expose technical details.

---

# Success Feedback

Success should be subtle.

A soft toast.

A smooth animation.

No loud confirmations.

No celebrations.

---

# Loading

Never leave blank screens.

Skeletons preferred.

Avoid spinners.

If loading exceeds expectations,

communicate progress.

---

# Forms

Keep forms short.

Group related fields.

Avoid long pages.

Smart defaults.

Auto-complete whenever possible.

---

# Scanning

Users scan before reading.

Hierarchy must support scanning.

Important information first.

Metadata second.

Secondary actions last.

---

# Accessibility

Large touch targets.

Readable typography.

Strong contrast.

Keyboard navigation.

Screen reader support.

Visible focus states.

---

# Mobile Experience

Thumb-first design.

Primary actions near the bottom.

Comfortable spacing.

Avoid tiny controls.

---

# Desktop Experience

Use whitespace.

Avoid stretching content edge-to-edge.

Readable content width.

Comfortable layouts.

---

# Motion

Motion explains.

Motion never decorates.

Animation should communicate:

Origin.

Destination.

Relationship.

Never animate for attention.

---

# Notifications

Only notify when necessary.

Avoid interruption.

Respect user focus.

---

# Trust

Users should always know:

Where they are.

What happened.

What happens next.

---

# Final Principle

Every interaction should leave the user feeling:

"That was easier than I expected."
